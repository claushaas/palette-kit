# Novas features para a v0.4

## Conversores para diversos formatos

```ts
const hexColor = theme.resolve({}).toHex();

const rgba = theme.resolve({}).toRgba();
```

Entregar a maior quantidade de formatos possíveis.

## Tipos com todos os nomes das cores 'variant'

Tipar todas as cores definidas como variants no createTheme para que seja mais simples escolher as variantes ao usar as funções para resolver as cores.

## resolver especial para textos

cor de texto não está resolvendo bem. O texto sempre deve responder ao colorScheme atual do dispositivo e a intensidade da cor sobre a qual ele está sobreposto.

Por exemplo, num contexto de colorScheme light, normalmente o texto se aproximaria mais do preto para ter um grande contraste, ou seja, um L baixo. No entanto, se nessa mesma situação ele estiver sobre um fundo sólido, com um L ainda relativamente baixo, ele precisa se aproximar do branco com um L alto.

O ideal é que fosse estabelecido o APCA ideal para cada uso de texto ()

## Color Query mais determinística e menos inferística

Desenvolver uma api para a color query que gere resultados semelhantes aos steps do radix, mas com a complexidade realmente necessária para que estado, ênfase, uso, tipo de superfície, etc. realmente façam diferença clara. De forma que todos os detalhes do uso da cor gerem o resultado, mas sem precisar inferir nada a partir dessa query. Cada característica dela deve gerar um resultado previsível dentro das combinações de chroma e lightness para todos os presets de apca desejados pelo dev. Ou seja, podemos excluir completamente a prop role.

## Resolvers

Devem usar os seguintes parâmetros para chegar a cor ideal:

- Uso
- Estado
- Intenção
- Contexto
- Ênfase
- Hierarquia
