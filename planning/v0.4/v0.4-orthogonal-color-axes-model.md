
# Palette Kit v0.4 — Orthogonal Color Axes Model

---

## Central Axis: Usage (WHERE)

### Definition

**Usage** defines *where* a color is physically applied in the interface.

It does not encode meaning, importance, or interaction.
It only answers the question:

> Where is this color used?

### Allowed Values (Closed Set)

Palette Kit v0.4 defines exactly four usages:

- **Fill**
- **Visual Vocabulary**
- **Lines**
- **Overlays**

This set is minimal, exhaustive, and stable.

---

### 1. Fill

#### Fill usage

##### Fill: What it represents

Solid colored areas.

Includes:

- backgrounds
- surfaces
- containers
- cards
- panels
- buttons
- any filled shape

#### Why Fill is unified

##### Fill: Why it is unified

From a physical and perceptual standpoint, background and fill are the same thing.
Any difference between them is semantic, not structural.

---

### 2. Visual Vocabulary

#### Visual Vocabulary usage

##### Visual Vocabulary: What it represents

All symbolic units that communicate meaning directly.

Includes:

- text
- icons
- emojis
- glyphs
- pictograms

#### Why Visual Vocabulary is unified

##### Visual Vocabulary: Why it is unified

These elements are:

- read, not perceived atmospherically
- semantically explicit
- contrast-critical
- foreground by nature

Separating text and icons at the usage level fragments contrast logic and semantic reasoning.

---

### 3. Lines

#### Line usage

##### Line: What it represents

Stroke-based structural elements.

Includes:

- borders
- dividers
- outlines
- separators
- grid lines

#### Why Lines are distinct

##### Line: Why it is distinct

Lines are neither areas nor symbols.
They serve spatial and structural roles and typically operate at lower chroma and contrast.

---

### 4. Overlays

#### Overlay usage

##### Overlay: What it represents

Colors applied on top of existing content, usually via alpha blending.

Includes:

- scrims
- modal backdrops
- hover overlays
- pressed states
- selection overlays
- shimmer and glow effects

#### Why Overlays are distinct

##### Overlay: Why it is distinct

Overlays are physically different from solid colors:
they rely on composition and cannot be reasoned about in isolation.

---

## Orthogonal Axes

The following axes are **independent of Usage**.

They modify or contextualize a color, but never redefine where it is applied.

---

### Intent (WHY)

Defines semantic meaning.

Examples:

- success
- danger
- warning
- info
- brand
- neutral

Intent answers *why the color exists*, not where it is used.

---

### State (WHEN)

Defines temporal or interactive conditions.

Examples:

- default
- hover
- active
- focus
- disabled
- loading

State operates on top of a base color.
It never creates a new usage.

---

### Hierarchy (RELATIVE IMPORTANCE)

Defines importance relative to similar elements.

Examples:

- primary
- secondary
- tertiary

Commonly applied to actions, text, and icons.

---

### Emphasis (STRENGTH)

Defines visual strength.

Examples:

- subtle
- default
- strong

Often implemented via changes in luminance, chroma, or alpha.

---

### Context (ENVIRONMENT)

Defines the environment in which resolution happens.

Examples:

- light / dark mode
- surface depth
- theme
- high-contrast mode

Context changes the resolved output, not the semantic structure.

---

## Completeness Proof

All common UI color cases decompose cleanly into these axes:

- shadows → overlays
- highlights → overlays or contextual fills
- selections → overlays
- charts → fills + lines + visual vocabulary
- focus rings → lines or overlays
- skeletons → fills
- shimmer → overlays

No valid color application escapes this model.

---

## Why This Model Matters

This orthogonal approach enables:

- fewer tokens
- simpler resolvers
- stronger inference
- predictable evolution
- zero semantic leakage between concerns

Most design systems fail because they mix axes implicitly.
Palette Kit makes them explicit.

---

## Final Summary

- **Usage** defines the physical placement.
- **Intent** defines meaning.
- **State** defines time.
- **Hierarchy and Emphasis** define perception.
- **Context** defines environment.

Each axis answers one question — and only one.

This separation is the foundation of Palette Kit v0.4.
