# Palette Kit v0.4 — Formal Color Resolution Matrix

## Purpose

This document defines the **formal color resolution matrix** used by Palette Kit v0.4.

The matrix describes how **usage-driven constraints** interact with Intent and State
within the full v0.4 axis model:

- **Usage** — where the color is applied
- **Intent** — why the color exists semantically
- **Level** — how strong / deep it is
- **Relation** — how it relates to another surface
- **State** — when the color is being used
- **Context** — in which environment it is resolved

The objective is to make all constraints, invariants, and degrees of freedom
**explicit, predictable, and enforceable**.

---

## Resolution Pipeline

Color resolution follows the SPEC pipeline:

Validate inputs  
↓  
Intent direction  
↓  
Usage strategy selection  
↓  
Level application  
↓  
Relation application (on | over | under)  
↓  
State operators  
↓  
Context adjustments  
↓  
Output serialization

This matrix focuses on **usage, intent, and state constraints** within that pipeline.

---

## 1. Usage × Physical Constraints

This table defines which color dimensions are allowed to vary depending on **Usage**.

| Usage | Luminance (L) | Chroma (C) | Hue (H) | Alpha | Contrast Requirement |
| ----- | ------------- | ---------- | ------- | ----- | -------------------- |
| Fill | Primary axis | Allowed | Free | Rare | Contextual |
| Visual Vocabulary | Constrained | Limited | Free | Forbidden | Strict |
| Lines | Constrained | Minimal | Free | Allowed | Relaxed |
| Overlays | Derived | Derived | Free | Primary axis | Contextual |

---

## 2. Usage × Semantic Influence

This table defines how strongly **Intent** is allowed to influence the resolved color.

| Usage | Semantic Weight | Typical Intents |
| --- | --- | --- |
| Fill | Medium | neutral, brand, success, warning, danger, info |
| Visual Vocabulary | High | success, danger, warning, info, brand |
| Lines | Low | neutral, brand (rare) |
| Overlays | Low | neutral (common), any registered intent |

---

## 3. Usage × State Operators

This table summarizes default operator focus **when a state is applied**.
State availability is not restricted by usage; operators are configurable.

| Usage | Default Operators |
| --- | --- |
| Fill | Luminance delta, optional chroma, optional alpha |
| Visual Vocabulary | Small luminance delta only |
| Lines | Luminance delta, alpha |
| Overlays | Alpha scaling, optional luminance delta |

---

## 4. Forbidden Transformations

This table lists **explicitly disallowed operations**.

| Usage | Forbidden Changes |
| --- | --- |
| Fill | Large hue shifts on interaction |
| Visual Vocabulary | Alpha usage, chroma amplification |
| Lines | High chroma colors, semantic hue shifts |
| Overlays | Absolute luminance control |

---

## 5. Intent × Usage — Default Bias Matrix

This matrix defines **default semantic affinity**, not hard rules.

| Intent | Fill | Visual Vocabulary | Lines | Overlays |
| --- | --- | --- | --- | --- |
| Neutral | High | High | High | High |
| Brand | High | Medium | Low | Low |
| Success | Medium | High | Low | Low |
| Warning | Medium | High | Low | Low |
| Danger | Medium | High | Low | Low |
| Info | Medium | High | Low | Low |

---

## 6. Hard Resolution Invariants

The resolver must always guarantee:

- Usage constraints are enforced first
- Visual Vocabulary contrast rules are never violated
- States are composable and reversible
- Identical inputs produce identical outputs
- No axis leaks responsibility into another

---

## 7. Example Resolution Walkthrough

### Input

usage: visualVocabulary  
intent: danger  
state: hover  
context: dark

### Resolution Steps

1. Usage enforces strict contrast and forbids alpha  
2. Intent selects the semantic hue family  
3. State applies a small luminance delta  
4. Context adapts the result for dark mode  
5. Output is validated against contrast thresholds  

---

## Final Summary

This resolution matrix ensures that:

- color behavior is deterministic
- constraints are explicit
- the system scales without combinatorial explosion
- future axes can be added without breaking existing contracts

If a color decision cannot be explained using this matrix,
it does not belong in Palette Kit.

This document defines the **operational backbone** of Palette Kit v0.4.
