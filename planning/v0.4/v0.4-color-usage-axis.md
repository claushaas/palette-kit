# Palette Kit v0.4 — Color Usage Axis: A Minimal, Structural Model

## Purpose

This document formalizes the **Color Usage axis** adopted in Palette Kit v0.4.

The goal is to define **where colors are used**, and *only that* —  
independent of intent, hierarchy, state, or semantic meaning.

This axis answers a single question:

> **Where is this color physically applied in the interface?**

Everything else (meaning, importance, state, interaction) belongs to **orthogonal axes**.

---

## Core Principle

A **usage** is defined by **structural placement**, not by:

- semantic intent (success, danger, brand)
- hierarchy (primary, secondary, muted)
- interaction state (hover, active, disabled)
- visual strength (strong, subtle, inverse)

If an element remains the *same kind of thing*, it is the **same usage**, even if it varies in meaning or importance.

---

## The Minimal Set of Color Usages

After collapsing all redundant and historical distinctions, Palette Kit defines **four and only four** color usages.

These usages are:

- exhaustive
- mutually exclusive
- orthogonal
- physically grounded

---

## 1. Fill

### Fill definition

`Fill` represents any solid colored area.

This includes what is traditionally called:

- backgrounds
- surfaces
- fills
- containers
- cards
- buttons
- panels

### Fill rationale

From a technical and perceptual standpoint:

- a background and a fill are the same thing
- both are solid areas defined by luminance and chroma
- their difference is semantic, not physical

Separating `background` and `fill` introduces duplication, ambiguity, and unnecessary rules.

Therefore, they are unified under a single usage: **Fill**.

---

## 2. Visual Vocabulary

### Visual Vocabulary definition

`Visual Vocabulary` represents all symbolic units that convey **explicit meaning**.

This includes:

- text
- icons
- emojis
- pictograms
- glyphs

### Visual Vocabulary rationale

These elements:

- are read directly by the user
- communicate meaning explicitly, not atmospherically
- require strict contrast guarantees
- function as semantic foreground

They differ in shape, but not in perceptual role.

Treating text and icons as separate usages fragments contrast logic and semantic reasoning.

Grouping them under **Visual Vocabulary** reflects how humans actually read interfaces.

---

## 3. Lines

### Lines definition

`Lines` represent all stroke-based elements used for structure and separation.

This includes:

- borders
- dividers
- outlines
- strokes
- separators
- table grid lines

### Lines rationale

Lines are:

- not areas
- not symbolic units
- not overlays

They serve spatial and structural purposes and typically operate at lower chroma and contrast.

They deserve their own usage category to avoid conflating them with fills or foreground content.

---

## 4. Overlays

### Overlays definition

`Overlays` represent any color applied **on top of other content**, usually via alpha blending.

This includes:

- scrims
- modal backdrops
- hover overlays
- pressed states
- selection overlays
- disabled overlays
- shimmer and glow effects

### Overlays rationale

Overlays are physically different from solid colors:

- they rely on alpha composition
- they interact with whatever is beneath them
- their appearance cannot be reasoned about in isolation

Treating overlays as simple backgrounds leads to visual bugs and contrast failures.

They must be modeled as a distinct usage.

---

## Completeness Check

All common UI color cases can be decomposed into these four usages:

- shadows → overlays
- highlights → overlays or contextual fills
- selections → overlays
- charts → fills + lines + visual vocabulary (labels)
- focus rings → lines or overlays
- skeletons → fills
- shimmer → overlays

No valid color application escapes this model.

---

## Why This Matters

This reduction enables:

- a simpler resolver
- stronger inference
- fewer tokens
- clearer mental models
- long-term extensibility without API breakage

Most design systems fail by mixing:

- usage
- intent
- state
- appearance

Palette Kit explicitly separates them.

---

## Final Model Summary

The **Color Usage axis** in Palette Kit v0.4 consists of:

- **Fill**
- **Visual Vocabulary**
- **Lines**
- **Overlays**

Nothing more. Nothing less.

All other distinctions belong to other axes.

This minimal model is not a limitation — it is what makes the system robust, composable, and future-proof.
