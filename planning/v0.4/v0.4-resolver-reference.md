# Palette Kit v0.4 — Resolver Reference

## API & Behavioral Contract

## Purpose

This document is the **practical reference** for the Palette Kit resolver API.

It explains:

- every resolver option
- what each option does to the color
- what each option explicitly does **not** do
- valid and invalid combinations

This document is optimized for **daily usage**, not architecture review.

If you want theory, read the SPEC.  
If you want to *use* the resolver correctly, read this.

---

## Resolver Entry Point

```ts
palette.resolve(options)
```

The resolver:

- is pure
- deterministic
- side-effect free
- stateless

---

## ResolveOptions (Complete)

```ts
type ResolveOptions = {
  usage: Usage
  intent: Intent
  level?: Level
  on?: ResolvedColor
  over?: ResolvedColor
  under?: ResolvedColor
  state?: State
  context?: Context
  output?: ColorOutput
}
```

All behavior is driven by these options.
Nothing else influences resolution.

---

## usage (required)

```ts
usage: "fill" | "visualVocabulary" | "lines" | "overlays"
```

### What it controls

- resolver strategy
- allowed relations
- which color channels may change (L, C, H, α)

### What it never controls

- hue selection
- contrast strength
- environment
- state

### Examples

```ts
usage: "fill"        // surfaces
usage: "lines"       // borders, separators
usage: "visualVocabulary" // text, icons, emojis
usage: "overlays"    // overlays, shadows
```

---

## intent (required)

```ts
intent: Intent
```

### What it controls

- hue
- base chroma

### What it never controls

- lightness
- contrast
- opacity
- usage

### Notes

- Intent must exist in the Intent Registry
- Unknown intents throw errors
- Overlays may use any intent; `neutral` is the common default

---

## level (conditionally required)

```ts
level: 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 | 9
```

### What it controls

- relative intensity / depth
- target luminance (L)

### Required for

- fill
- lines
- overlays

### Forbidden for

- visualVocabulary

### Notes

- Level is never inferred
- Interpretation depends on usage

---

## on / over / under (optional but constrained)

```ts
on?: ResolvedColor
over?: ResolvedColor
under?: ResolvedColor
```

Only one of `on`, `over`, or `under` may be provided.

### on

**Purpose**

- enforce contrast
- guarantee legibility

**Used by**

- text
- icons
- lines on surfaces

**Effects**

- adjusts L first
- reduces chroma if needed
- never changes hue

---

### over

**Purpose**

- layering
- translucent overlays

**Used by**

- overlays only

**Effects**

- applies alpha
- minimal luminance shift
- no contrast enforcement

---

### under

**Purpose**

- depth
- shadows

**Used by**

- overlays only

**Effects**

- applies alpha
- reduces luminance
- no contrast enforcement

---

## state (optional)

```ts
state:
  | "default"
  | "hover"
  | "active"
  | "focus"
  | "selected"
  | "disabled"
```

### What it controls

- small reversible deltas

### Effects

- modifies L and/or α slightly
- never changes intent
- never changes relation
- never changes level

### Notes

- Disabled always reduces perceived prominence
- States never stack

---

## context (optional override)

```ts
context: "light" | "dark"
```

### What it controls

- luminance interpretation
- contrast direction
- perceptual curves

### Precedence

1. resolver-level context
2. palette-level context
3. system default

---

## output (optional)

```ts
output: "oklch" | "oklab" | "srgb" | "p3" | "hex" | "rgba"
```

### What it controls

- serialization format only

### Notes

- resolution always happens in OKLCH
- output never affects semantics

## Common Valid Examples

### Solid surface

```ts
palette.resolve({
  usage: "fill",
  intent: "brand",
  level: 3
})
```

---

### Text on surface

```ts
palette.resolve({
  usage: "visualVocabulary",
  intent: "neutral",
  on: surface
})
```

---

### Hover state

```ts
palette.resolve({
  usage: "fill",
  intent: "info",
  level: 4,
  state: "hover"
})
```

---

### Shadow

```ts
palette.resolve({
  usage: "overlays",
  intent: "neutral",
  level: 2,
  under: surface
})
```

---

## Invalid Examples (by design)

```ts
// ❌ level not allowed for visualVocabulary
palette.resolve({
  usage: "visualVocabulary",
  intent: "neutral",
  level: 2
})
```

```ts
// ❌ overlays cannot use on
palette.resolve({
  usage: "overlays",
  intent: "neutral",
  on: target
})
```

## Resolver Guarantees

If resolution succeeds:

- output is deterministic
- contrast is enforced only when requested
- no hidden inference occurred
- no global state was mutated

---

## Summary

The resolver:

- combines explicit axes
- applies them in a fixed order
- emits a predictable result

If something feels surprising:

- an option is missing
- or an invalid combination was attempted

This document is the **operational contract**
of the Palette Kit resolver.
