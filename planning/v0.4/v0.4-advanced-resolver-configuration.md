# Palette Kit v0.4 — Advanced Resolver Configuration

## Purpose

This document defines the **advanced configuration layer** of the Palette Kit resolver (v0.4).

It is intended for **system authors and design system maintainers** who require
fine‑grained control over perceptual behavior, without breaking the guarantees,
predictability, and mental model of the default system.

This document does **not** redefine how the resolver works.
It defines **how its parameters can be customized explicitly**.

---

## Design Principles

1. **Defaults are safe and complete**  
   No configuration is required for correct usage.

2. **All customization is explicit**  
   No hidden heuristics or environment‑dependent behavior.

3. **Customization changes magnitude, not meaning**  
   Axes remain orthogonal; configuration never mixes responsibilities.

4. **Runtime determinism is preserved**  
   Same inputs + same config = same outputs.

---

## Configuration Entry Point

Advanced configuration is provided at palette creation time.

```ts
const palette = createPaletteKit({
  context: "light",
  resolverConfig: defaultResolverConfig
})
```

The resolver never mutates this configuration at runtime.

---

## ResolverConfig Shape

```ts
export type ResolverConfig = {
  levelCurves: LevelCurveConfig
  stateDeltas: StateDeltaConfig
  relationParams: RelationConfig
  chromaLimits: ChromaConfig
}
```

Each section controls a **single responsibility**.

---

## Level Curves

Controls how `level` maps to target luminance.

```ts
type LevelCurveConfig = {
  fill: (level: Level, context: Context) => number
  lines: (level: Level, context: Context) => number
  overlays: (level: Level, context: Context) => {
    alpha: number
    luminanceDelta?: number
  }
}
```

### Default Behavior

- Fill levels map to a Radix‑like luminance curve
- Lines compress luminance deltas aggressively
- Overlays derive alpha as the dominant channel

---

## State Deltas

Defines reversible, temporary deltas applied by `state`.

```ts
type StateDeltaConfig = {
  luminance: {
    hover: number
    active: number
    focus: number
    selected: number
    disabled: number
  }
  alpha: {
    hover: number
    active: number
    focus: number
    selected: number
    disabled: number
  }
}
```

### Default Percentages (of usable L range)

| State | ΔL |
| ----- | ---- |
| hover | ±3% |
| active | ±6% |
| focus | ±4% |
| selected | ±5% |
| disabled | −10% |

Alpha deltas apply **only** to usages that allow alpha.

---

## Relational Parameters

Defines behavior for `on`, `over`, and `under`.

```ts
type RelationConfig = {
  on: {
    contrastTarget: number
    maxLuminanceShift: number
  }
  over: {
    baseAlphaByLevel: Record<Level, number>
  }
  under: {
    baseAlphaByLevel: Record<Level, number>
    luminanceReduction: number
  }
}
```

### Rules

- `on` enforces contrast strictly
- `over` and `under` never enforce contrast
- `under` always reduces luminance

---

## Chroma Limits

Defines chroma fallback behavior.

```ts
type ChromaConfig = {
  maxReduction: number
  reductionStep: number
}
```

Chroma is reduced **only when contrast or gamut cannot be satisfied otherwise**.

---

## Overriding Defaults

Users may override selectively:

```ts
const palette = createPaletteKit({
  resolverConfig: {
    ...defaultResolverConfig,
    stateDeltas: {
      ...defaultResolverConfig.stateDeltas,
      luminance: {
        hover: 0.04,
        active: 0.08
      }
    }
  }
})
```

Partial overrides are merged explicitly.

---

## Non‑Goals

Advanced configuration must never:

- introduce new semantics
- infer missing inputs
- bypass contrast guarantees
- mutate resolved colors post‑hoc

---

## Summary

Advanced Resolver Configuration exists to:

- support extreme brands
- tune perceptual intensity consciously
- preserve system predictability

This document defines **how to customize the engine without breaking it**.
