# Palette Kit v0.4 — Implementation Playbook

## Purpose

This document is the **authoritative execution guide** for implementing Palette Kit v0.4.

It translates the SPEC into **small, linear, low-cognitive-load phases**, optimized for:

- fast iteration
- small PRs
- minimal mental branching
- zero architectural reinterpretation

If followed strictly, this playbook:

- prevents implementation out of order
- reduces bug surface
- keeps the system aligned with the v0.4 contracts

---

## Core Rules (Read First)

1. **Never skip a phase**
2. **Never merge phases**
3. **Prefer stubs over partial logic**
4. **Every phase must compile**
5. **No phase introduces heuristics**
6. **No phase reinterprets the SPEC**

---

## High-Level Architecture Layers

Implementation progresses **topologically**, not by feature:

1. Mathematical core
2. Semantic registries
3. Resolution axes
4. Resolver pipeline
5. Environment & relations
6. Serialization
7. DX & safety layers

---

## Phase Breakdown

Each phase below is intentionally small.
Most phases should fit in **1–3 focused sessions**.

---

## Phase 0 — Repository & Build Baseline

**Goal**  
Ensure a clean, stable baseline before any logic.

### Must implement

- Freeze previous version
- Create v0.4 branch
- Green build (lint, typecheck, tests)

### May stub

- Nothing

### Must NOT skip

- This phase gates all others

---

## Phase 1 — Canonical Color Model

**Goal**  
Define the internal color representation.

### Must implement

- OKLCH data structure
- Normalization rules
- Validation helpers

### Files

- `src/core/oklch.ts`

### May stub

- Conversions
- Gamut handling

### Must NOT

- Serialize
- Resolve semantics
