# Palette Kit v0.4 — Relational Axis Specification (on | over | under)

## Purpose

This document formalizes the **Relational Axis** in Palette Kit v0.4.

The Relational Axis defines how a color is resolved **in relation to another already resolved color**.
It makes explicit whether the relationship is about **contrast**, **layering**, or **depth**.

The axis answers the question:

> **How does this color relate to another surface or color in the visual stack?**

---

## Core Principle

Not all relationships between colors are the same.

Palette Kit distinguishes three fundamentally different relationships:

- **on** — contrast and legibility
- **over** — visual overlay and layering
- **under** — subposition and shadowing

Each relationship has:

- a different physical goal
- different constraints
- different valid usages
- different resolution strategies

They must never be conflated.

---

## Relation Targets

```ts
export type RelationTarget = BaseResolvedColor
```

Relations are expressed via resolver options:

```ts
resolve({ ..., on: surface })
resolve({ ..., over: surface })
resolve({ ..., under: surface })
```

---

## Relationship Semantics

### 1. `on` — Contrast Relationship

#### `on` definition

`on` defines a **contrast relationship**.
It is used when a color must be **perceptually distinguishable and legible**
against another color.

#### `on` primary goal

- guarantee perceptual contrast

#### `on` typical usages

- visualVocabulary (text, icons, glyphs)
- outlines that must be readable
- indicators with semantic meaning

#### `on` resolution characteristics

- measures contrast against the target
- adjusts luminance directionally (L ↑ or L ↓)
- preserves hue
- reduces chroma only if required
- never uses alpha for text

#### `on` non-goals

- depth
- elevation
- atmospheric effects

---

### 2. `over` — Overlay Relationship

#### `over` definition

`over` defines a **layering relationship**.
It is used when a color sits **on top of another surface**
without requiring semantic contrast.

#### `over` primary goal

- communicate layering and interaction

#### `over` typical usages

- overlays
- hover layers
- pressed states
- selection highlights
- glass / scrim effects

#### `over` resolution characteristics

- alpha is the primary control
- luminance and chroma are derived
- influenced by `level`
- does not enforce contrast thresholds

#### `over` non-goals

- legibility guarantees
- semantic signaling

---

### 3. `under` — Subposition Relationship

#### `under` definition

`under` defines a **subposition relationship**.
It is used when a color must appear **beneath** another surface,
creating a sense of depth or shadow.

#### `under` primary goal

- communicate elevation and separation

#### `under` typical usages

- shadows
- inner shadows
- depth cues
- recessed surfaces

#### `under` resolution characteristics

- alpha-driven
- luminance shifts downward
- chroma strongly constrained
- hue usually neutral or inherited
- strongly influenced by `level`

#### `under` non-goals

- semantic meaning
- contrast guarantees
- legibility

---

## Relationship to Other Axes

The Relational Axis is orthogonal to all other axes.

| Axis | Question Answered |
| ---- | ---- |
| Usage | Where is the color applied? |
| Intent | Why does this color exist? |
| Level | How strong / deep is it? |
| State | When is it applied? |
| Relation | How does it relate to another surface? |

No axis replaces another.

---

## Usage Compatibility

Not all usages support all relations.

| Usage | on | over | under |
| ---- | ---- | ---- | ---- |
| fill | optional | invalid | invalid |
| visualVocabulary | required | invalid | invalid |
| lines | optional | invalid | invalid |
| overlays | invalid | required | required |

Violations are rejected at the type system level where possible,
and validated at runtime otherwise.

---

## Typing Rules (Capability Example)

```ts
visualVocabulary: {
  on: BaseResolvedColor
  over?: never
  under?: never
}

overlays: {
  over?: BaseResolvedColor
  under?: BaseResolvedColor
  on?: never
}
```

This ensures compile-time guidance and prevents semantic misuse.

---

## Resolution Guarantees

The resolver must guarantee that:

- `on` always enforces contrast rules
- `over` and `under` never enforce contrast
- no relation changes semantic intent
- relations are explicit and never inferred
- results are deterministic and explainable

---

## Why This Axis Exists

Without explicit relational modeling:

- shadows become magic constants
- overlays break in dark mode
- contrast logic leaks into semantics
- visual systems become fragile

The Relational Axis ensures that **physical relationships**
are modeled directly, not approximated.

---

## Example

```ts
const surface = resolve({
  usage: "fill",
  intent: "neutral",
  level: 1
})

const buttonFill = resolve({
  usage: "fill",
  intent: "brand",
  level: 4,
  on: surface
})

const buttonShadow = resolve({
  usage: "overlays",
  intent: "neutral",
  level: 2,
  under: surface
})

const buttonText = resolve({
  usage: "visualVocabulary",
  intent: "neutral",
  on: buttonFill
})
```

Each relation is explicit.
Each behavior is predictable.
No heuristics are hidden.

---

## Final Summary

The Relational Axis formalizes **how colors interact**, not just what they are.

- `on` handles contrast
- `over` handles layering
- `under` handles depth

Together, they allow Palette Kit to model real visual systems
without semantic hacks or magic tokens.

This document defines the **Relational Axis contract** for Palette Kit v0.4.
