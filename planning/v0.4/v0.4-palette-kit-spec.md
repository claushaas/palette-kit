# Palette Kit — SPEC v0.4 (Final)

## 1. Purpose

Palette Kit v0.4 defines a **deterministic, declarative, and perceptual color resolution engine**.

This SPEC unifies all architectural, semantic, and type-level contracts into a single source of truth. If an implementation follows this document, its behavior will be:

- predictable
- explainable
- testable
- difficult to misuse

Palette Kit is **not** a theme generator.
It is a **color resolution system**.

---

## 2. Core Design Principles

1. No implicit behavior
2. No hidden heuristics
3. No magic tokens
4. Orthogonal axes
5. Deterministic resolution
6. Explicit configuration
7. Deep customization without breaking guarantees

---

## 3. Mental Model

Color resolution is the result of combining **independent axes**:

| Axis | Question answered |
| ---- | ---- |
| Usage | Where is the color used? |
| Intent | Why does the color exist? |
| Level | How strong / deep is it? |
| Relation | How does it relate to another surface? |
| State | When is it applied? |
| Context | In which environment is it resolved? |

No axis infers another.

---

## 4. Usage Axis

```ts
type Usage =
  | "fill"
  | "visualVocabulary"
  | "lines"
  | "overlays"
```

Usage selects:

- resolver strategy
- allowed relations
- allowed channels

Overlays commonly use `neutral`, but any registered intent is allowed.

---

## 5. Intent Axis

```ts
type Intent =
  | "neutral"
  | "brand"
  | "success"
  | "warning"
  | "danger"
  | "info"
```

Intent defines:

- hue family
- chroma target

The intent registry is app-owned.
Additional intents may be defined via theme configuration.

---

## 6. Level Axis

```ts
type Level = 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 | 9
```

Level is:

- explicit
- never inferred
- interpreted per usage

Forbidden for `visualVocabulary`.

---

## 7. Relational Axis

```ts
type RelationTarget = ResolvedColor
```

### Semantics

- `on` → contrast & legibility
- `over` → overlay & layering
- `under` → depth & shadow

The relational axis is expressed via resolver options:

```ts
on?: RelationTarget
over?: RelationTarget
under?: RelationTarget
```

---

## 8. State Axis

```ts
type State =
  | "default"
  | "hover"
  | "active"
  | "focus"
  | "selected"
  | "disabled"
```

State applies **small reversible deltas**.

---

## 9. Context Axis

```ts
type Context = "light" | "dark"
```

Context is:

- environmental
- defined globally
- overrideable locally
- never inferred

---

## 10. Resolver API

```ts
palette.resolve({
  usage,
  intent,
  level?,
  on?,
  over?,
  under?,
  state?,
  context?,
  output?
})
```

---

## 11. Context Precedence

1. Resolver-level context
2. Palette-level context
3. System default

No heuristics.
System default is provided by the host environment
and injected by the developer.

---

## 12. Default Resolver Behavior

Each option corresponds to a **documented transformation**:

| Option | Affects |
| ------ | -------- |
| intent | Hue, base chroma |
| level | Target luminance |
| on | Contrast (ΔL, fallback C) |
| over | Alpha |
| under | Alpha + L↓ |
| state | Small deltas |
| context | Curves & thresholds |

---

## 13. Default Deltas (Baseline)

### State Luminance Deltas

| State | ΔL |
| ---- | ---- |
| hover | ±3% |
| active | ±6% |
| focus | ±4% |
| selected | ±5% |
| disabled | −10% |

### Overlay / Shadow Alpha (example)

| Level | over α | under α |
| ---- | ---- | ---- |
| 1 | 0.04 | 0.06 |
| 2 | 0.08 | 0.10 |
| 3 | 0.12 | 0.16 |
| 4 | 0.18 | 0.22 |

---

## 14. Advanced Resolver Configuration

All numeric behavior is configurable via `ResolverConfig`:

```ts
type ResolverConfig = {
  levelCurves
  stateDeltas
  relationParams
  chromaLimits
}
```

Defaults are safe.
Overrides are explicit.

---

## 15. Presets

```ts
type Preset = "soft" | "neutral" | "strong"
```

Presets:

- adjust magnitude only
- never change semantics
- map to predefined ResolverConfig

---

## 16. Type System Contract

The type system guarantees:

- invalid combinations are unrepresentable
- relations are explicit
- level is never inferred
- context is deterministic

If it compiles, it is conceptually valid.

---

## 17. What Palette Kit Never Does

Palette Kit never:

- guesses missing axes
- infers context
- mixes responsibilities
- mutates global state
- uses magic tokens
- optimizes for aesthetics alone

---

## 18. Resolver Pipeline (Deterministic)

1. Validate inputs
2. Apply intent
3. Select usage strategy
4. Apply level
5. Apply relation
6. Apply state
7. Apply context
8. Emit resolved color

---

## 19. Output & Serialization

Palette Kit separates **color resolution** from **color delivery**.

All colors are resolved in a canonical perceptual space (OKLCH).
Serialization happens as a final, configurable step.

---

### Output Formats

```ts
type ColorOutput =
  | "oklch"
  | "oklab"
  | "srgb"
  | "p3"
  | "hex"
  | "rgba"
```

---

### Configuration

```ts
const palette = createPaletteKit({
  context: "light",
  output: "rgba"
})
```

Override per resolver call:

```ts
palette.resolve({
  usage: "fill",
  intent: "brand",
  level: 4,
  output: "hex"
})
```

---

### Precedence

1. Resolver-level output
2. Palette-level output
3. System default (`oklch`)

The system default is provided by the host environment
and injected by the developer.

---

### Guarantees

Serialization:

- never alters resolved color semantics
- never applies semantic logic
- never changes contrast or accessibility
- may clamp or fallback only when the explicit output strategy allows it

This preserves determinism and platform compatibility.

## 21. Final Statement

Palette Kit v0.4 is defined by **explicitness**.

If a color behaves a certain way, it is because:

- it was declared
- it was configured
- it was documented

Nothing else.

This document is the **final normative specification**
for Palette Kit v0.4.
