# Palette Kit v0.4 — Testing Strategy & Golden Cases

## Purpose

This document defines **how Palette Kit v0.4 must be tested**.

Its goal is not visual validation.
Its goal is to guarantee **semantic, mathematical, and behavioral invariants**.

If these tests pass:

- the system is correct
- refactors are safe
- regressions are detectable

---

## Core Testing Principle

> **Palette Kit tests invariants, not aesthetics.**

Tests must never assert:

- that a color “looks good”
- that a value matches a designer’s expectation
- that two colors are subjectively similar

Tests must assert:

- determinism
- contract compliance
- axis isolation
- absence of inference

---

## Test Layers Overview

Testing is divided into **four layers**, from lowest to highest risk.

1. Mathematical invariants
2. Semantic invariants
3. Resolver pipeline invariants
4. Golden cases

Each layer builds on the previous one.

---

## 1. Mathematical Invariants

### Scope

Low-level color math and conversions.

### Must Test

- OKLCH normalization
- OKLCH → OKLab → OKLCH round-trip
- Precision stability within tolerance
- No NaN or Infinity propagation

### Must NOT Test

- perceptual quality
- contrast adequacy

### Example Assertions

```ts
expect(roundTrip(oklch)).toBeCloseTo(oklch, EPSILON)
```

---

## 2. Semantic Invariants

### Scope

Intent Registry and axis rules.

### Must Test

- unknown intent throws
- intent lookup is deterministic
- intent does not encode level or usage
- registry immutability after creation

### Must NOT Test

- specific hues
- domain meaning

---

## 3. Resolver Pipeline Invariants

### Scope

Axis combination and execution order.

### Must Test

- same input → same output
- changing output format does not change internal OKLCH
- resolver order is fixed
- forbidden axis combinations fail

### Critical Invariant

```text
resolve(A) === resolve(A)
```

for identical inputs, regardless of call order or frequency.

---

## Axis Isolation Tests

Each axis must be independently testable.

### Examples

- changing `state` does not affect `intent`
- changing `level` does not affect `hue`
- changing `on` / `over` / `under` does not affect `usage`
- changing `output` does not affect resolution

If any of these fail, the architecture is broken.

---

## 4. Golden Cases

### Purpose

Golden cases are **canonical scenarios** that must never change unintentionally.

They are not exhaustive.
They are representative.

---

## Golden Case Selection Rules

Golden cases should:

- cover all usages
- cover all relations
- include light and dark contexts
- include at least one failure case

They must be few and stable.

---

## Recommended Golden Cases

### Case 1 — Solid Surface

```ts
resolve({
  usage: "fill",
  intent: "brand",
  level: 3,
  context: "light"
})
```

Asserts:

- valid OKLCH
- deterministic output
- no alpha

---

### Case 2 — Text on Surface

```ts
resolve({
  usage: "visualVocabulary",
  intent: "neutral",
  on: surface
})
```

Asserts:

- contrast enforced
- hue preserved
- alpha = 1

---

### Case 3 — Divider Line

```ts
resolve({
  usage: "lines",
  intent: "neutral",
  level: 2,
  on: surface
})
```

Asserts:

- reduced chroma
- alpha < 1
- no contrast overreach

---

### Case 4 — Shadow

```ts
resolve({
  usage: "overlays",
  intent: "neutral",
  level: 1,
  under: surface
})
```

Asserts:

- alpha applied
- luminance reduced
- no contrast enforcement

---

### Case 5 — Failure Case

```ts
resolve({
  usage: "visualVocabulary",
  intent: "brand",
  level: 3
})
```

Asserts:

- throws with clear error

---

## Snapshot Testing (Careful Use)

Snapshots may be used only for:

- serialized output
- fixed precision formats

Snapshots must never be used for:

- internal OKLCH
- contrast math

---

## Regression Strategy

When behavior changes intentionally:

1. Update SPEC
2. Update this document
3. Update golden cases

Never update golden cases alone.

---

## CI Recommendations

- run tests in strict mode
- fail on warnings in CI
- disallow flaky tolerances

---

## Summary

- Test invariants, not visuals
- Golden cases are contracts
- Determinism is non-negotiable
- Axis isolation is sacred

This document defines the **Testing Strategy & Golden Cases Contract**
for Palette Kit v0.4.
