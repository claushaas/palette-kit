# Palette Kit v0.4 — Type System Contract (Updated)

## Purpose

This document defines the **Type System Contract** for Palette Kit v0.4.

It formalizes how types enforce:

- semantic correctness
- axis orthogonality
- resolver predictability
- prevention of invalid combinations

The type system is not cosmetic.
It is a **first-class enforcement layer** of the design system.

---

## Core Design Principles

1. **No implicit behavior**
2. **All axes are explicit**
3. **Invalid states are unrepresentable**
4. **Types reflect conceptual reality**
5. **DX must guide correct usage**

---

## Orthogonal Axes Overview

Palette Kit models color resolution through independent axes:

| Axis | Responsibility |
| ---- | ---- |
| Usage | Where the color is used |
| Intent | Why the color exists |
| Level | How strong / deep it is |
| Relation | How it relates to another surface |
| State | When it is applied |
| Context | In which environment it is resolved |

Each axis has strict typing rules.

---

## Usage Axis

```ts
type Usage =
  | "fill"
  | "visualVocabulary"
  | "lines"
  | "overlays"
```

Usage selects:

- the resolver strategy
- allowed relations
- allowed channels (L, C, H, α)

Usage never encodes state or intent.

---

## Intent Axis

```ts
type Intent =
  | "neutral"
  | "brand"
  | "danger"
  | "success"
  | "warning"
  | "info"
```

Intent defines:

- hue family
- chroma target

Intent never defines:

- contrast
- level
- relation

Intent is defined by the app-owned registry.
Additional intents may be registered via theme configuration.

---

## Level Axis

```ts
type Level = 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 | 9
```

Level defines **relative intensity or depth**.

Rules:

- Required for `fill`, `lines`, `overlays`
- Forbidden for `visualVocabulary`
- Interpreted differently per usage
- Never inferred

---

## Relational Axis

```ts
type RelationTarget = PaletteResolveOutput<ColorOutput>
```

### Relation Semantics

- `on` → contrast & legibility
- `over` → overlay & layering
- `under` → depth & shadow

Relations are explicit and mutually exclusive.
Only one of `on`, `over`, or `under` may be provided for a given resolve call.

Resolver options express relations as:

```ts
on?: RelationTarget
over?: RelationTarget
under?: RelationTarget
```

Relation targets may be normalized OKLCH or any serialized Palette Kit output.
Implementations normalize them back to OKLCH before applying relation logic.

---

## Relation Compatibility Matrix

| Usage | on | over | under |
| ---- | ---- | ---- | ---- |
| fill | optional | ❌ | ❌ |
| visualVocabulary | ✅ required | ❌ | ❌ |
| lines | optional | ❌ | ❌ |
| overlays | ❌ | ✅ | ✅ |

Invalid combinations must be rejected at compile time where possible.

---

## State Axis

```ts
type State =
  | "default"
  | "hover"
  | "active"
  | "focus"
  | "selected"
  | "disabled"
```

State:

- applies small reversible deltas
- never changes semantic meaning
- never affects intent or relation

---

## Context Axis

```ts
type Context = "light" | "dark"
```

Context is **environmental**.

Rules:

- Defined at palette creation
- Optional override at resolver call
- Never inferred automatically
- Does not affect semantic axes

---

## Resolver Options Type

```ts
type ResolveOptions = {
  usage: Usage
  intent: Intent
  level?: Level
  on?: RelationTarget
  over?: RelationTarget
  under?: RelationTarget
  state?: State
  context?: Context
  output?: ColorOutput
}
```

`ColorOutput` is defined in the Output & Serialization Contract.

---

## Usage-Specific Constraints (Examples)

### visualVocabulary

```ts
type VisualVocabularyOptions = {
  usage: "visualVocabulary"
  intent: Intent
  on: RelationTarget
  level?: never
  over?: never
  under?: never
}
```

### overlays

```ts
type OverlayOptions = {
  usage: "overlays"
  intent: Intent
  level: Level
  over?: RelationTarget
  under?: RelationTarget
  on?: never
}
```

---

## Resolver Configuration Typing

```ts
type ResolverConfig = {
  levelCurves: LevelCurveConfig
  stateDeltas: StateDeltaConfig
  relationParams: RelationConfig
  chromaLimits: ChromaConfig
}
```

This configuration:

- is immutable
- provided at palette creation
- never inferred

---

## Presets Typing

```ts
type Preset = "soft" | "neutral" | "strong"
```

Presets map to predefined `ResolverConfig` objects.

---

## Context Precedence (Typed)

```ts
effectiveContext =
  options.context
  ?? palette.context
  ?? systemDefaultContext
```

This rule is fixed and unambiguous.

---

## Type System Guarantees

The type system guarantees that:

- semantic misuse is prevented
- relations are explicit
- levels are never inferred
- context is predictable
- resolvers are deterministic

---

## Non-Goals (Explicit)

The type system must never:

- encode visual heuristics
- infer missing axes
- auto-correct semantic mistakes
- hide resolver behavior

---

## Summary

Palette Kit v0.4 uses the type system as a **semantic firewall**.

If something compiles:

- it is conceptually valid
- its behavior is predictable
- its output is explainable

This document defines the **Type System Contract** for Palette Kit v0.4.
