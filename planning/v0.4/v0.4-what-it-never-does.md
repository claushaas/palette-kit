# Palette Kit v0.4 — What Palette Kit Never Does

## Purpose

This document defines **explicit non-goals** of Palette Kit v0.4.

It exists to eliminate ambiguity, prevent incorrect assumptions,
and set clear boundaries for what the system **intentionally does not do**.

These constraints are as important as features.
They preserve predictability, trust, and long-term maintainability.

---

## Palette Kit Never Infers Missing Information

Palette Kit never:

- guesses `level`
- guesses `intent`
- guesses `relation`
- guesses `usage`
- guesses `context`

If a decision matters, it must be **explicitly declared**.

Missing inputs are surfaced as:

- type errors
- runtime validation errors
- or documented defaults — never heuristics

---

## Palette Kit Never Mixes Axes

Palette Kit never:

- encodes state into intent
- encodes intensity into intent
- encodes contrast into usage
- encodes depth into semantics
- encodes environment into color meaning

Each axis has a single responsibility.
Axes remain orthogonal at all times.

---

## Palette Kit Never Uses Magic Tokens

Palette Kit never introduces tokens like:

- `textOnPrimary`
- `borderStrong`
- `surfaceElevated`
- `overlayHeavy`

All such concepts are expressed through:

- `usage`
- `level`
- `relation`
- `state`

There are no hidden variants.

---

## Palette Kit Never Hides Contrast Logic

Palette Kit never:

- silently flips colors
- silently changes hue
- silently ignores contrast rules
- silently lowers accessibility requirements

Contrast behavior is:

- explicit (`on`)
- deterministic
- explainable
- testable

---

## Palette Kit Never Auto-Detects Environment

Palette Kit never:

- reads system theme automatically
- infers light/dark from background color
- switches context implicitly

Environment (`context`) is:

- explicitly set at palette creation
- optionally overridden per resolver call

---

## Palette Kit Never Mutates Global State

Palette Kit never:

- relies on global mutable config
- changes behavior at runtime implicitly
- leaks configuration across instances

All configuration is:

- immutable
- instance-scoped
- deterministic

---

## Palette Kit Never Optimizes for Aesthetics Alone

Palette Kit never:

- picks colors because they "look nice"
- encodes taste or trends
- hides trade-offs

All decisions are grounded in:

- perceptual models
- explicit configuration
- documented intent

---

## Palette Kit Never Prevents Deep Customization

Palette Kit never:

- locks internal parameters
- hides coefficients
- forbids overrides

Advanced users may customize:

- deltas
- curves
- thresholds
- presets

Responsibility is explicit and assumed.

---

## Summary

Palette Kit v0.4 is defined as much by what it **refuses to do** as by what it enables.

It never:

- guesses
- hides
- infers
- mutates
- surprises

If something happens, it is because:

- it was declared
- it was configured
- or it was explicitly documented

This document defines the **non-negotiable boundaries**
of Palette Kit v0.4.
